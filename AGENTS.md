# AlanBlast — Project Instructions

## Project vision

AlanBlast is a free, mobile-first block puzzle game inspired by Block Blast, prioritizing satisfying gameplay, fairness, responsiveness and audiovisual polish.

The game should capture the appeal of Block Blast while using original code, graphics, sounds and branding.

## Non-negotiable principles

- No advertisements.
- No microtransactions.
- No pay-to-win mechanics.
- No monetization-driven difficulty adjustments.
- No hidden manipulation of player outcomes.
- No analytics or personal data collection.
- All gameplay rules must be consistent and transparent.
- The game must be playable offline after the initial load.

## Technical requirements

- HTML5, CSS and vanilla JavaScript.
- No unnecessary frameworks or dependencies.
- Hosted on GitHub Pages.
- Installable Progressive Web App (PWA).
- Compatible with Android, iOS and desktop browsers.
- Prioritize mobile performance and 60 FPS animations.
- Use local storage for scores, settings and game progress.
- Use relative asset paths for GitHub Pages compatibility.

## Gameplay requirements

- 8×8 block puzzle board.
- Three available pieces per round.
- Drag-and-drop controls.
- Accurate placement previews.
- Simultaneous row and column clearing.
- Combo and streak scoring systems.
- Full-board clearing bonuses.
- Theme changes following full-board clears.
- Game-over detection.
- Persistent high scores.
- Fair, documented piece generation.

## Game feel

Prioritize:

- Responsive touch controls.
- Smooth block pickup and placement.
- Satisfying clearing animations.
- Particle effects.
- Sound effects.
- Haptic feedback where supported.
- Animated scoring.
- Seamless theme transitions.

## Development rules

- Keep gameplay logic separate from rendering and input.
- Write modular, maintainable code.
- Test gameplay logic whenever changes are made.
- Do not remove existing functionality without approval.
- Do not introduce new dependencies without justification.
- Document gameplay design decisions.
- Report modified files, completed tests and known limitations after every task.
